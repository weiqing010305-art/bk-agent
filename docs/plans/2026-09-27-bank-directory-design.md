# 常用联系人与银行演示名录分离

用户明确要求：数据库有某个人，不代表此人是常用联系人；应能通过卡号查询并转账。

实现：
- 演示名录仍有 10 位人物，新增 is_favorite，仅王女士、张三、李四默认常用。
- 数据库迁移兼容当前场景，不删除人物、余额或账单。
- /api/state 仅返回常用联系人；POST /api/recipients/lookup 根据完整卡号查询同场景名录。
- 前端手动输入去除空白，300ms 延迟查询，显示加载、失败、重试与匹配姓名；过时响应不覆盖新号码。
- 核对草稿再次由后端查询收款人，查号结果不能伪造收款身份。查号和转账都不会自动添加常用联系人。
- 同场景的名录仍用于模拟外部收款人，不是新增真实用户登录或真实跨行服务。

验证：30 项 API 测试、3 项账本测试与构建通过，包含非联系人查号、未命中、跨场景隔离和常用名单不变。
