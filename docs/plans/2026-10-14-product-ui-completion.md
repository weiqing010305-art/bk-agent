# 产品讨论 UI 落地计划

**Goal:** 根据 product-discussion 文档完善可视化与手动操作，保留首页、十三个业务入口及既有资金确认流程，暂不开发 Agent。

**Architecture:** UI 读取同一份 bank.transactions；统计为纯派生函数，不另造金额和历史。支付沿用 EverydayServices/payService，卡片管理沿用原账本与 gate；新增展示与键盘交互，不更改受保护架构。

**Tech Stack:** React、CSS tokens、Lucide、原生 SVG/CSS、Playwright，无新依赖。

## 方向与范围

选择强化最具体的生活缴费场景，并修齐银行卡交互。全面改版会破坏已确认首页，只换颜色无法回应讨论中的信息可视化，因此沿用当前白底、统一薄荷图标，浅蓝/暖杏仅用于少量信息与图表。

1. **生活缴费**：水电燃气选择、按月的金额构成和最近六个月趋势、可筛选的缴费记录及再次缴费。所有金额来自账本；再次缴费只填写户号和类型，金额重新输入。没有欠费接口，不推测“待缴金额”。
2. **共用服务流程**：手机/交通卡充值、生活缴费、信用卡还款、兑换及网点预约添加三步进度与明确回执，保留原表单、密码校验、查询未知结果和防重复支付。
3. **银行卡**：卡面提供键盘左右/Home/End 切换，明确卡名和状态，关联 tabpanel；金额与卡号隐藏覆盖相关字段。近期交易从同一账本读取，未归属具体卡的交易不强行分配。
4. **储蓄与账单**：储蓄目标用进度、剩余金额、状态分层呈现，修改目标定位表单；账单补齐现有交易类别筛选，日净支出保留负号。
5. **验证**：派生数据边界单测；浏览器核对缴费三类型、空/有数据、月份/类别筛选、再次缴费不扣款、卡片键盘及隐藏、13 个入口、手机布局；运行现有单测、构建、后端集成、文档检查，记录旧脚本适配情况。

## 本轮边界

暂不新增对话行为、Agent、模型调用和自由生成 UI。不批量写入虚构历史、不改资金 API；现有本地卡片管理和其他本地功能的存储范围维持原状。讨论文档的研究建议不被自动视为本轮实现项。
