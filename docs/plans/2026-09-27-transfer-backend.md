# PostgreSQL 模拟转账 Implementation Plan

**Goal:** 在唯一现有 mock 上接通数据库支持的模拟转账，保留原有视觉设计。

**Architecture:** Vite 同源代理到 FastAPI；PostgreSQL 存储隔离的演示用户、会话、账户、收款人、流水、不可变转账草稿、授权和审计事件。金额统一整数分。账户行锁串行化扣款，幂等键绑定请求摘要，流水和余额在一个事务内提交。

**Tech Stack:** React / FastAPI / SQLAlchemy 2 / Alembic / PostgreSQL 16 / pytest / Playwright。

## 已确认范围与设计

- 用户已确认使用数据库并推进下一阶段，不再创建三个 mock。
- 保留显式纯前端模式；用环境变量启用后端模式。后端断开时禁止转账，不偷偷切换本地成功。
- 首版使用匿名、独立的演示会话，不是真实银行登录。HttpOnly Cookie、会话有效期、来源检查与自定义请求头用于本地演示边界。
- 创建草稿 → 核对服务器返回的参数 → 用户确认 → 显式模拟验证码 → 原子记账 → 回执。草稿不可修改，返回修改时创建新草稿，旧授权不能挪用。
- 首版记账是同库事务内的模拟银行模块，不是历史设计中的独立 bank-sim / worker。不宣称实现分布式 UNKNOWN 对账；客户端网络失败保持原操作编号并查询结果，不重新转账。
- 订阅、卡片继续本地演示，单独标注。无真实模型、真实银行、真实个人资料。
- PostgreSQL 使用容器卷，Git 仅保存建表迁移、样例代码和环境模板。

## 实施与验收

1. 数据层：添加 Compose、依赖、迁移、独立种子函数。验证建表/回滚/再次升级。
2. API：会话、状态、草稿、确认挑战、验证并记账、结果查询、重置。验证非法金额、余额不足、对象归属、过期、错误验证码、幂等冲突。
3. 并发：重复同操作只记一次；不同操作并发不能透支；授权与流水同事务。
4. 前端：保留布局，显式连接状态，核对服务器数据，验证码与错误/重试/回执、刷新恢复待处理编号。
5. 回归：原 Node/浏览器测试、API 测试、后端模式浏览器测试、生产构建。
6. 文档：运行命令、数据边界、实现与历史架构差异、验证结果。未请求自动推送本次改动。
