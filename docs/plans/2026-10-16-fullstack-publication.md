# 前后端统一运行与 GitHub 发布计划

日期：2026-10-16。依据用户要求「前后端合并，然后上传 github」。

## 目标与取舍

保留当前同仓前后端、十三业务及已有数据边界，增加构建后页面与 API 同源运行入口。开发代理继续用于热更新；另加反向代理会增加部署组件，因此使用现有 FastAPI 托管 Vite 的 dist。只合并运行和交付方式，不新增 Agent、业务或依赖，不修改受保护产品架构。

## 实施步骤

1. 为前端静态托管补测试：根页面、旧预览地址、资源文件可读取；API 路由仍优先；缺构建文件时 API 独立可用；源代码及环境文件不可读取。
2. 新增 `backend/frontend.py`，在既有 API 注册完成后挂载 dist；未构建时不挂载。扩展 `scripts/start-dev.mjs`，提供 `npm start`：准备数据库、迁移、以 backend 模式构建，然后启动同源应用。兼容 Windows 和 POSIX 虚拟环境路径。
3. 同步 README、后端说明、架构及决策记录，保留 `.env.example`；本机 .env、数据库、缓存、截图和工具不入库。
4. 运行前后端单元、构建、合并入口和原后端集成检查；新版产品 UI 和文档检查覆盖本次发布。旧导航套件的已知限制如实记录。
5. 仅提交已检查的项目源码、文档和测试，核对远端 main，正常推送到用户现有仓库；推送后比对远端提交与本地提交，不使用 force。
