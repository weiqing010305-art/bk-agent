# 银行 AI 资金管家（bk-agent）

> 面向个人客户的 AI Banking Agent：用自然语言理解用钱需求，结合账户、账单与周期支出生成**可解释**的资金方案，并在**分级授权**下完成银行操作。

本仓库是金融科技大赛参赛作品的**设计文档集（v2.0 评审稿）**。当前阶段交付的是需求、架构、接口契约、页面流程与验收清单，尚未进入代码实现。

## 一句话定位

用户可以直接说「给房东转 3000 元」，也可以说「下个月买电脑，但不能影响房租和还款」。系统既支持单项业务办理，也支持持续跟踪的资金计划。

产品不做「通用金融问答」，而是把每一笔分析结论都锚定到具体的交易、账单或用户设定上，让用户能核查、能修正错误假设。

## 六项业务能力

| 编号 | 模块 | P0 必做 | P1 增强 |
|---|---|---|---|
| F1 | 智能转账 | 按联系人检索、备注转账、立即转账、到期确认式定时转账 | AA 账单及收款进度、预授权定时执行 |
| F2 | 订阅管理 | 周期扣费候选、协议核对、续费提醒、模拟取消 | 扣费涨价与疑似重复订阅提示 |
| F3 | 账单分析 | 分类与纠正、月度分析、区间对比、异常候选、明细追溯 | 年度报告、自定义维度 |
| F4 | 卡片管理 | 卡片状态、临时冻结、解冻、挂失、关联交易查询 | 限额调整、渠道限制、模拟卡申请 |
| F5 | 未来现金流预警 | 30 天预测、账单日历、余额低点、缺口解释、操作前影响试算 | 多情景收入延迟、90 天预测 |
| F6 | 目标资金计划 | 目标创建、两种安排方案、资金分配、冲突检测、执行跟踪、变化后重规划 | 长周期目标、用户授权的限额规则 |

跨模块能力：Web 页面、AI 侧栏、任务中心、结构化确认卡、模拟强验证、站内通知、操作记录、样例账户切换、可复现演示。

## 技术栈一览

| 部分 | 选型 |
|---|---|
| Web | React 19 + TypeScript + Vite，Ant Design、ECharts |
| 后端 | Python 3.12、FastAPI、Pydantic 2 |
| 数据 | PostgreSQL 16、SQLAlchemy 2 + Alembic + psycopg 3 |
| Agent 编排 | LangGraph + PostgreSQL checkpointer（只管理对话流程，不承载交易事实） |
| 长期任务 | 独立 worker 进程 + PostgreSQL 任务表与 outbox（不引入 Redis / Kafka / Celery） |
| 模拟银行 | 独立 bank-sim 服务，与服务凭据隔离 |
| 测试 | pytest、Vitest、Playwright |
| 本地交付 | Docker Compose：web / api / worker / bank-sim / postgres |

## 架构一眼看懂

```text
浏览器 ──同源 /api── API 应用 ──内部 HTTP── bank-sim
                         │
                         ├── 主 Agent → 模型 API（配置注入）
                         ├── 业务 / 授权 / 预测 / 目标
                         └── app + agent schemas
                                      ↑
                                  worker
                          到期检查、执行、核查、通知
```

核心原则：**页面操作和自然语言交互走同一个应用服务、同一套授权规则**。AI 通过工具调用业务能力，不持有任何直连银行的执行工具，所有写操作都经过分级确认与记录。

## 当前状态与边界

- 本仓库内容为**设计与契约**，不是已完成实现的系统，也不是测试报告。
- 比赛版本运行在**自建模拟银行**上：模拟账户、模拟交易、模拟强验证，人民币，统一业务时区与可控演示时钟。
- 明确的**不纳入**范围：IM 接入、理财申购赎回、外部商城下单。
- 模型供应商与精确依赖补丁版本待初始化时确定；无模型凭据时可先用显式回放模式联调，但实时 Agent 验收保持「未通过」状态，不以回放冒充模型理解能力。
- 文档中的产品目标为**待验证假设**，不预先宣称转化率提升或行业领先。

## 第一条可运行闭环

```text
演示登录 → 查询账户 → 表单创建转账草稿 → 核对
       → 模拟强验证 → 模拟银行记账 → 回执 → 刷新余额
```

先跑通身份、接口、数据与授权链路，再把同一个操作接入自然语言发起。
