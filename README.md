# 青禾 · 银行 AI 资金管家（bk-agent）

面向个人客户的 AI Banking Agent 参赛项目。产品希望让用户用自然语言提出银行业务需求，并通过可核查的账单、账户信息和确认步骤完成操作。**当前保留一个 Web mock，并加入 PostgreSQL + FastAPI 模拟转账闭环**：核对、模拟验证码、数据库记账与回执。所有数据均为虚构。

## 当前进度

本次更新详情见 [更新记录](doc/CHANGELOG.md)。

| 阶段 | 范围 | 状态 |
|---|---|---|
| 第一阶段：前端 mock | 响应式 Web chatbot、四项核心业务、统一模拟数据 | 已实现，可本地运行 |
| 第二阶段：后端转账 | 独立演示会话、PostgreSQL 余额/账单、模拟验证、幂等记账 | 已实现，见后端运行说明 |
| 后续阶段：AI Agent | 意图理解、业务工具调用与授权流程 | 尚未接入 |
| 扩展方向 | 现金流预警、目标资金计划等 v2.0 设计构想 | 暂不纳入当前 mock |

这个项目聚焦具体的银行业务，不做通用金融问答。用户可以提出“给张三转 100 元”或“这个月花了多少”这样的需求；当前 mock 会按关键词进入对应流程，具体收款人与金额仍需在卡片中填写。产品目标是让分析结果能追溯到交易，让重要操作能先核对再确认。更长周期的资金规划是历史设计稿中的后续方向。

## 运行 mock

**体验数据库版：先按 [后端运行说明](backend/README.md) 启动 PostgreSQL、执行迁移并运行 FastAPI，再启动前端。** `.env` 中配置 `VITE_API_MODE=backend`。不配置该变量时，以下命令仍运行原来的纯前端 mock。

需要 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

打开 <http://127.0.0.1:5173/>。运行 `npm test` 检查模拟账本，运行 `npm run build` 检查构建。启动开发服务后，安装 Microsoft Edge 的机器可运行 `npm run test:e2e` 检查浏览器流程。

## 当前可体验的业务

| 业务 | mock 中可操作的流程 | 数据反馈 |
|---|---|---|
| 智能转账 | 选择 3 位常用联系人，或输入完整演示卡号查询银行名录中的其他人物，再核对转账 | 数据库有 10 位虚构人物；无需添加联系人即可转账，未知卡号或余额不足会拦截 |
| 账单分析 | 查看九月收支、分类分布，筛选交易明细 | 与转账后的账本保持一致 |
| 订阅管理 | 查看自动续费项目，确认模拟取消 | 项目状态与预计下月扣费同步变化 |
| 卡片管理 | 查看两张样例卡，确认模拟冻结或解冻 | 卡片状态同步变化 |

首页提供四项业务快捷入口，也可输入包含“转账”“账单”“订阅”“卡片”等关键词的消息。对话区独立滚动，输入框固定在底部；切换业务后，旧操作卡片收起，可点“重新打开”。`Ctrl/⌘ + K` 可开始新对话。

“新对话”不会删除旧聊天：左侧历史列表按首条用户消息自动命名，可随时切回，每段对话独立保留消息、未发送输入、转账表单和分类筛选，刷新后恢复。历史保存在当前浏览器，不跨设备同步；浏览器清除站点数据后无法恢复。验证码不保存到历史，有确认弹窗或请求进行时暂不能切换对话。重置演示账户会保留旧对话；其中的业务卡片展示当前账户数据，历史消息/回执保留原文，不是历史账本快照。启用此功能前已经被旧版“新对话”清掉的消息无法找回。

所有余额、交易、卡片和订阅均为**虚构演示数据**，聊天回复由预设规则生成；当前没有接入真实 AI 模型、银行系统或支付通道。模拟转账和取消订阅不会产生真实操作。演示记账日期固定为 2026 年 9 月 25 日。纯前端模式使用 localStorage；后端模式将余额、账单、收款人、操作、授权和审计保存在 PostgreSQL，卡片/订阅仍在浏览器本地。界面顶部明确显示连接状态和边界，断线不切换账本。“重置演示数据”在后端模式创建新场景，不删除旧审计记录。

## 实现概览

历史对话每行右侧提供删除按钮，确认后移除该条消息和草稿，刷新后保持删除结果。删除当前对话会切到另一条，删除最后一条会新建空白对话。仅删除本浏览器聊天，不影响银行余额、交易、审计记录，也不撤销转账；删除后无法恢复。

前端使用 React 19、JavaScript/JSX、Vite 和 CSS。`src/bank.js` 保存纯前端模拟逻辑，`src/main.jsx` 实现对话与业务卡片，`src/api.js` 处理同源接口，`src/TransferDialog.jsx` 实现服务器核对与模拟验证。`src/style.css`、`src/refinement.css` 保留青禾绿色三栏布局和手机适配。`backend/` 使用 FastAPI、SQLAlchemy、Alembic 和 PostgreSQL 16；Compose 数据卷不进入 Git。测试包括 Node 单元测试、真实 PostgreSQL API/并发测试以及两种模式的 Playwright 浏览器测试。
