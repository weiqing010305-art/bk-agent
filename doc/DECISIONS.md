# DECISIONS — 需要产品判断的决策台账

> 这不是「待办清单」，是**需要人拍板的产品逻辑问题**。
> 每条都附：现状、为什么这是产品问题（而不是技术问题）、备选方案、我的倾向。
>
> 判断标准（作者给的）：
> 1. 是否设计好了用户使用动线
> 2. 呈现的内容是否符合预期
> 3. 页面是否过于复杂或混乱
>
> 维护义务见 [AGENTS.md](../AGENTS.md) §2。最后更新：2026-09-28

## 决策量表（用文字解释设计 ⇄ 用设计代替文字）

本轮所有页面都在朝「少文字」走。但**少不等于好**，两个方向都会翻车：

```
用文字解释设计           恰到好处           过度设计
（认知负荷高）                              （猜不出来）
      │                     │                    │
  "活期账户合计"       图标 + 数字 + 分组      纯色块无标签
  每行一个说明句                            用户不知道那是什么
```

**每个决策都要在这个量表上表态**，而不是无脑删字。

## D-01 · 免责声明要不要放在界面上

**现状**：界面上原有 18 处「演示环境不产生真实交易」「演示对话由预设规则驱动」这类文字。
已按你的要求**全部删除**（含你点名的 `Composer.jsx` 输入框下方那句）。

**为什么是产品问题**：
一个银行 Demo，**不写免责声明**在道德上有风险 —— 万一有人以为是真的。
但写在界面上确实是在「用文字替设计道歉」，而且出现在每一页。

**备选**：

| 方案 | 界面字数 | 风险 |
| --- | --- | --- |
| A. 完全不写（当前） | 0 | 观感最干净；靠演示场景本身说明 |
| B. 顶栏一个常驻小徽标（如「沙盒」） | 1-2 | 一句话说清，不占正文 |
| C. 仅在首次进入时一次性提示 | 0（常驻） | 首次有点烦 |
| D. 每页页脚保留 | +8/页 | **直接违反 150 字硬指标** |

**我的倾向**：**B**。一个词的小徽标，位于顶栏右侧，不进入任何页面的字数预算。
这是唯一同时满足「诚实」和「干净」的做法。

**需要你定**：选哪个？

## D-02 · 150 字这个口径本身

**现状**：测量时分两个口径 ——
- **界面文案**（标签、标题、说明句、按钮）
- **数据**（列表行、金额、日期、商户名）

**为什么是产品问题**：
「单页 ≤150 字」如果连数据一起算，**账本页永远不可能达标** ——
100 条流水的商户名就是 100 个词。那不是在优化设计，是在自欺。

实测（当前口径下）：

| 页面 | 界面文案 | 数据 |
| --- | ---: | ---: |
| 卡片 | 613 | 67 |
| 转账 | 319 | 0 |
| 收款人 | 287 | 0 |
| 概览 | 246 | 2067 |
| 助手·首页 | 234 | 0 |
| 订阅 | 183 | 236 |
| 账单 | 146 | 585 |

**我的倾向**：**维持两口径**，把 150 字锁在「界面文案」上。
数据不计入，但**数据过多本身是另一个问题**（见 D-03）。

**需要你定**：认可这个口径吗？还是你要的是「连数据一起算」？

## D-03 · 概览页的「动态」到底该多长

**现状**：概览页的动態渲染了 **148 行流水**（界面文案 246 字，数据 2067 字）。
它是全站数据量最大的地方。

**为什么是产品问题**：
- 这不只是「字多」，是**动线问题**：用户在概览页看到的应该是「我现在需要知道什么」，
  而不是「全部历史」。
- 148 行放在概览页，等于把账单页又做了一遍。

**备选**：
| 方案 | 效果 |
| --- | --- |
| A. 只显示 5-8 条 + 「全部」入口 | 概览回归"概览"，明细归账单页 |
| B. 保留长列表但按时间折叠 | 用户仍要滑 |
| C. 保持现状 | 概览与账单职责重叠 |

**我的倾向**：**A**，并且明确「概览 = 状态，账单 = 明细」的分工。

**需要你定**：概览页的动態保留几条？

## D-04 · 助手页底部那排功能 chips 留不留

**现状**：输入框上方有 **7 个 chips**（转账 / 账单 / 订阅 / 卡片 / 定时转账 / AA 收款 / 跨场景），
下方还有一行**历史条 chips**。也就是**两排长得像的东西**。

**为什么是产品问题**（这正是你点名的那个例子）：
- 它和**左侧导航重复**：左侧已有概览/账单/订阅/卡片/收款人/回执/转账
- 它挤占纵向空间，而工作区是「一屏看全」的
- 两排 chips 让用户分不清「哪个是历史、哪个是功能」

**备选**：
| 方案 | 效果 |
| --- | --- |
| A. 全删 | 靠左侧导航 + 自然语言，最干净；但发现性变差 |
| B. 只留一个最高频的 | 减少噪音，但没解决"和导航重复" |
| C. 保留但换个形态（如换成图标、或收进一个"+"） | 视觉更轻 |
| D. 把历史条和功能条合并成一个 | 消除"两排很像"的困惑 |

**我的倾向**：**D + C**（合并成一排，功能用图标而非文字 chip）。
理由：两排 chips 是这一页最明显的"混乱"来源，而左侧导航已经承担了发现性。

**需要你定**：留 / 删 / 换形态？

## D-05 · 5 秒撤销窗口要不要扩展到所有执行动作

**现状**：只有转账有 5 秒撤销（来自众安的做法）。
但冻结卡片、取消订阅、调整限额同样是"不可逆"的。

**为什么是产品问题**：
撤销窗口是**摩擦的分配问题** —— 加在哪里、不加在哪里，直接决定用户的安全感与效率感。

**我的倾向**：扩展到所有**写操作**（冻结、取消订阅、限额调整），
但**查询类不加**（那会让"直接执行"变成"处处要等"）。

**需要你定**：同意吗？

## D-06 · 概览页的宫格：「收款」与「收款人」进的是同一个页面

**现状**：宫格从 12 格砍到 **7 格**（删了 5 个只为占位的格子，它们点下去只换一句免责声明）。
但保留的 7 格里，圆形的「收款」和方形的「收款人」**路由到同一个页面**。

**为什么是产品问题**：一个格子代表一个去处。两个格子去同一个地方，用户会以为它们不同，
点进去发现一样 —— 那是认知浪费。

**备选**：删掉「收款」变 6 格 / 让「收款」有独立去处（发起收款请求，与收款人管理不同）/ 保持现状。

**我的倾向**：让「收款」有独立去处（发起一笔收款、生成收款码）。「收钱」和「管收款人」确实是两件事，
但这需要补业务。

**需要你定**：删一个，还是补业务？

## D-07 · 订阅页删掉了「占本月支出」那一格

**现状**：Agent 发现那一格**恒为 0%** —— 账本的 spending 是整个账期口径，
每月订阅除以它四舍五入永远是 0。**一个永远是 0 的数字比没有更糟**，所以删了。

**为什么是产品问题**：「订阅占支出多少」是用户真正关心的（它回答「我养了多少长期负担」）。
删掉格子解决了假数字，但**没解决用户想知道这个**。

**备选**：改成「一年订阅 ÷ 一年支出」（口径就对了）/ 换成「订阅 ÷ 月收入」/ 只显示绝对值不显示比例。

**我的倾向**：改成**年度口径**。订阅天然是年度负担，用年度比更真实。

**需要你定**：换哪个口径？

## D-08 · 转账页删掉了「四种方式的差别」面板

**现状**：原本有一张表，列出四种转账方式（转给他人 / 本人互转 / 预约 / AA）的限额、到账时间、手续费。
Agent 判断它和 A2UI surface 第一步的四张方式卡**是同一件东西摆两遍**，删掉了。

**为什么是产品问题**：限额、到账时间、手续费是**用户决策需要的信息**。删掉重复是对的，
但**信息本身去哪了**？现在四张方式卡上只有名称。

**备选**：把关键差异**印在卡片上** / 保留一张可展开的对比 / 认为用户不需要
（真实转账 App 也很少在主流程展示费率）。

**我的倾向**：**在卡片上印一行最关键的差异（到账时间）**。「多久到」是用户真正在意的，
「多少钱」在免费转账时代已经不是问题。

**需要你定**：印什么在卡片上？---

## D-09 · 收款人页的动作按钮从文字变成图标

**现状**：「再转一笔」「设为常用」共 40 字 → 两个 44×44 图标按钮，
动作名进 `title` 与 `aria-label`。

**为什么是产品问题**：这是「用设计代替文字」的最激进一步。**图标能省 40 字，但图标是有歧义的** ——
不看 tooltip 不一定知道它是什么。

**备选**：图标 + 悬停显示文字 / 只在空间紧张时用图标 / 回到文字按钮（会回到 87 字）。

**我的倾向**：**保留图标，但这是全站唯一两处需要「学习」的图标**。
理由是这一页每一行都长得一样，文字按钮会形成 40 个字的一列噪音，压过姓名与金额。
如果评审觉得歧义，改回文字也只多 40 字（仍 ≤150）。

**需要你定**：图标可接受吗？

## D-10 · 动态从「全量 148 行」改成「预览 22 行」

**现状**：概览页的动态只显示「即将扣费 + 卡片事件 + 最近 3 个有动账的日子」，
全量明细在账单页。数据量从 2067 字降到 289 字。

**为什么是产品问题**：这**重新定义了概览与账单的分工** —— 概览 = 状态，账单 = 明细。
但也意味着**用户不能在概览页看到「上周三那笔」**，必须去账单页。

**备选**：保持预览（当前）/ 回到全量 / 预览 + 一个「全部」入口。

**我的倾向**：**当前方案 + 一个「全部」入口**。概览不该承担账本的职责。

**需要你定**：预览保留几天？

## D-11 · 定时转账 / AA 收款现在只在转账流程里

**现状**：底部 chips 从 7 个删到 4 个。删掉的三个里，**定时转账与 AA 收款是有真实业务的**
（它们能走通同一条 DAG），只是**入口从底部 chips 移到了转账第一步的两张卡片上**。

**为什么是产品问题**：这是**发现性 vs 噪音**的取舍。挪进流程里更合理（它们本来就是转账的变体），
但用户**不会再在首页看到「哦，还能定时转账」**。

**备选**：保持（藏在转账里）/ 恢复到底部 chips（会变 6 个）/ 在欢迎视图提一句（违反少字原则）。

**我的倾向**：**保持**。赛题要求的是「能力存在」而不是「入口显眼」，
而且自然语言（下个月 1 号自动给房东转房租）本来就是最自然的入口。

**需要你定**：接受吗？---

## D-12 · 卡片页删掉了「挂失补卡」——但赛题要求这个能力

**现状**：那是一个点下去只弹 toast 的死按钮（文案还含「演示」），Agent 把它删了。

**为什么是产品问题**：**赛题明确要求「卡片挂失」**。
现在这个能力在界面上**完全不可见**了 —— 权限分级里它有高风险档、多因子认证也支持它，
但**用户找不到入口**。

**备选**：恢复按钮并接真实流程（走多因子认证）/ 只在助手侧提供 / 保持删除。

**我的倾向**：**恢复，并接真实流程**。它是赛题点名的能力，
而且是权限分级最好的演示场景之一（高风险 → 多因子 → 不可逆）。

**需要你定**：优先级排在哪？我建议紧接理财域之后。

## D-13 · 理财域完全缺失（赛题明确要求）

**现状**：赛题「赛题任务」里列了**理财操作**。本项目**整个域不存在** ——
没有产品、没有持仓、没有收益、没有申购赎回。

**为什么是产品问题**：这是**赛题要求的空白**，不是漏做。但做多深是产品判断：
真实理财域（风险测评 → 开投资户 → 产品货架 → 申购 → 持仓 → 赎回 → 收益）工作量巨大，
而且**与 Agent 的关系需要重新设计** —— 合规上 Agent 不能给投资建议。

**备选**：

| 方案 | 范围 | 工作量 |
| --- | --- | --- |
| A. 最薄 | 只做「收益查询」（低风险，直接执行） | 小 |
| B. 中等 | A + 产品货架 + 申购流程（走高风险多因子） | 中 |
| C. 完整 | B + 风险测评 + 持仓管理 + 赎回 | 大 |

**我的倾向**：**B**。A 太薄（赛题说「理财操作」，只有查询不算操作）；
C 的边际收益低（风险测评是表单，与 Agent 的叙事关系弱）。

**需要你定**：A / B / C？

## D-14 · 「用设计代替文字」的边界在哪

**现状**：本轮把界面文案从 **2461 字砍到 748 字**（降 70%），全部页面 ≤150。

**做了什么**：标签变图标（卡片档案的 6 行「标签 + 值」变成图标 + 值）；
说明句变位置与分组（概览主卡不再写「活期账户合计」，靠位置表达归属）；
计数胶囊直接删（「全部 148 / 入账 4 / 支出 137」是噪音）；
图表图例变交互本身（滑过就高亮，不需要文字解释）；动作按钮变图标。

**为什么是产品问题**：**砍到某个点之后，用户就猜不出来了。**
这一轮还没到那个点，但已经能感到张力 ——
卡片页的账期条（账单日到还款日的进度）**没有文字也能看懂**；
收款人页的图标**需要悬停才知道**。

**我的倾向**：建立一条判定规则 ——
「**这个元素删掉文字后，用户第一次看到能不能在 3 秒内猜对？**」
能 → 用设计；不能 → 保留最短的文字，但用视觉权重压到最低。

**需要你定**：认可这条规则吗？还是你有更明确的边界？

## D-15 · 首页要不要用 ZA 的「一个控件两个方向」手法

**依据**：报告 §A 挖到 ZA 首页有一个图标同时承载两个动作 —— **上滑 = 转账 / 轻点 = 存入**。
一个控件代替两个按钮。

**为什么是产品问题**：这是「用设计代替文字」最漂亮的一招，但它**要求用户学习**。
ZA 敢用是因为它的用户天天开这个 App；我们的用户是评委，看一次。

**我的倾向**：**不用**。学习成本在「演示一次」的场景里不划算。
但值得写进答辩 —— 说明我们知道这个手法，也知道什么时候不该用。

**需要你定**：认同吗？

## D-16 · 首页那句问候语要不要做成每日变量

**依据**：报告挖到 ZA 官方影片里唯一一次设计定调 ——「簡單清晰的字體、生動的圖標、**每日變換的問候語**」。
报告的评价是：**「让它变」比「把它写好」更划算** —— 首页唯一那句文案做成变量。

**现状**：我们的首页标题固定写「你好，小禾」。

**为什么是产品问题**：改成每日变量是**零成本的情绪价值**（ZA 用一个变量换来了"这 App 活着"的感觉）。
但也可能显得轻浮 —— 银行产品的基调是稳重。

**备选**：固定问候 / 按时间变（早上好/下午好/晚上好）/ 按状态变（有账单到期时换成提醒）。

**我的倾向**：**按时间变**。最克制的一种，且是真的有用（告诉用户"现在"）。

**需要你定**：要吗？

## D-17 · 理财页的「对照表代替说服文案」要不要用

**依据**：报告 §A 的第 4 种模式 —— ZA 用一张对照表代替说服文案：
左列「你可能：見到機會但不懂投資 / 都市人日忙夜忙 / 資金有限投資太集中」，
右列「專業管理 / 專注自己 / 分散風險」，**每项 4 到 10 字**。

## D-18 · 改信息架构时怎么处理「老位置」

## D-19 · 插画预算投给哪里

**依据**：报告量化了 ZA 的 105 条插画资产 —— **70+ 用于营销/抽奖领奖，年报长图 14，

**为什么是产品问题**：我们**完全没有插画**（零依赖，且没有插画师）。
但"情绪价值"是你在前面明确提出过的要求。

这是同一笔预算的两种花法，动效更适合"操作中"，插画更适合"停留时"。

**需要你定**：接受「用动效代替插画」这个定位吗？

## D-20 · 理财页的榜单排布：几个榜、怎么措辞

**依据**：报告挖到 ZA 有 **8 种榜单**，标题全是**行为数据**、零评级语义：
「熱賣基金」（近 14 天认购宗数 Top3）、「最高派息基金」、「最受歡迎」（笔数 Top10）、
「投資者賺錢最多」（赚钱额 Top10）、「從事金融/保險/銀行業的人都在買」。

**为什么是产品问题**：这是**合规设计**，不只是文案风格 ——
银行不能推荐"好"的产品，只能呈现"别人在做什么"。措辞一变，法律性质就变了。

**现状**：我让理财 Agent 做 2-3 种榜单（方案 B），标题按这个口径写。

**我的倾向**：**做 3 种**（熱賣 / 最高派息 / 最受歡迎），够撑起一个货架页。
定义放脚注不放标题。

**需要你定**：3 种够吗？还是你想要某个特定的榜？
