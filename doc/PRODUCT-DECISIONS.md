## §2 工程与协作规约（原 AGENTS.md，已并入）

### 2.1 Ponytail：ultra

**全程开启，强度 ultra。** 阶梯（停在第一个成立的档位）：

1. 这东西需要存在吗？→ 不需要就删掉，用一行说明
2. 仓库里已经有了吗？→ 复用，不要重写
3. 语言/标准库能做吗？→ 用标准库
4. 原生平台能力覆盖了吗？→ CSS 优先于 JS
5. 已装的依赖能解决吗？→ **白名单只有 react / react-dom / lucide-react / vite / @playwright/test。其余一律不加**
6. 能一行写完吗？→ 一行
7. 只有到这一步才写最小可用代码

**ultra 的额外约束**：
- **删除优先于新增**。净增行数为正必须能说清为什么不能是负的
- **禁止投机性抽象**：只有一个实现的 interface、只有一个产品的 factory，全删
- **文件数越少越好**。拆分要有真实理由（复用 ≥2 处，或单文件超约 300 行）
- 有意的简化用 ponytail 注释标记天花板与升级路径

**例外（不可偷懒）**：输入校验、错误处理、安全、无障碍基础、**用户明确要求的东西**。

### 2.2 文档同步义务（强制）

**任何改变结构、数据流、接口、组件层级的改动，必须在同一次改动里更新文档。文档过期视为 bug。**

| 文档 | 职责 |
| --- | --- |
| doc/PRODUCT-DECISIONS.md（本文） | **产品决策唯一真源** |
| doc/ARCHITECTURE.md | 系统架构、组件树、数据流、状态机，**全部用 Mermaid** |
| doc/PRD.md | 产品需求：功能范围、交互、验收标准 |
| doc/SECURITY.md | 权限分级实现说明与已知风险清单（比赛必交） |
| doc/COMPETITION.md | 赛题拆解、评分维度、答辩脚本 |
| doc/CHANGELOG.md | 变更记录 |

Mermaid 必须是能渲染的合法语法 —— npm run test:docs 用真实解析器逐块验。

### 2.3 设计与代码规约

- **设计令牌唯一来源**：src/styles/tokens.css。组件里**禁止出现硬编码颜色字面量**
- **无 TypeScript**（当前决策）
- **样式分层**：tokens.css → base.css → 组件各自 CSS
- **无障碍是底线不是加分项**：流式内容 aria-live、弹窗焦点管理、prefers-reduced-motion 降级
- **中文输入法**：任何回车提交的输入框必须处理 compositionstart / compositionend
- **单文件 < 300 行**

### 2.4 验证义务

改动后必须跑真实命令，不许「看起来对」就交：

```bash

npm run build       # 构建
```

## §3 派生决策（由 §1 推导，可改，但不得与 §1 冲突）

### 3.1 字数的测量口径

U-06 说「单页 ≤150 字」。但**数据**（列表行、金额、日期、商户名）不是「文字指引」——
100 条流水的商户名会让账本页永远不可能达标，那不是优化设计，是自欺。

**所以分两个口径**：**界面文案**（标签 / 标题 / 说明句 / 按钮）计入 150 字；**数据**不计入。

**对话流里的「一页」= 最新那一回合** —— 对话流连续滚动，量整个容器会把全部历史算进来。

### 3.2 「用设计代替文字」的边界（3 秒判定规则）

U-05 要求少文字，但砍到某个点后用户就猜不出来了。判定规则：

> **这个元素删掉文字后，用户第一次看到能不能在 3 秒内猜对？**
> 能 → 用设计；不能 → 保留最短的文字，但用视觉权重压到最低。

### 3.3 空 / 错 / 加载三态

口径照抄众安**真实上线**的文案（一手证据：投资子站 887 条 UI 字串表）：

| 态 | 结构 | 众安原文 |
| --- | --- | --- |
| 空 | 4 字状态 + 1 个按钮 | 頁面不見了 / 暫無記錄 |
| 错 | 拟人化标题 + 错误码 + 1 个动作 | 服務器開小差了 / 錯誤碼 / 刷新 |
| 加载 | **零文字** | 887 条字串里 loading 只命中 3 处，全与 PDF 有关 |

**错误从不解释技术原因，道歉不超过一句。拒绝 = 原因 + 补救路径。**

### 3.4 理财域的合规措辞

U-09 要求对标众安理财逻辑。众安的榜单标题全是**行为数据**（「熱賣基金」= 近 14 天认购宗数 Top3），
**零评级语义**。这不是文案风格，是**合规设计** —— 银行不能推荐「好」的产品，只能呈现「别人在做什么」。

### 3.5 动线的两种含义（消歧）

U-11 说动线必须无感，U-18 说每一步要看得见。两者不冲突，因为指的是两件事：

- **用户动线**（无感）= 体验的顺滑度。界面上**不放**流程图 / 管线面板
- **任务编排**（可见）= 用户自己的多步任务（如定时转账的 8 节点 DAG），有中断 / 回退 / 接管

### 3.6 合并协作者分支的方法（由 U-15 / U-42 派生）

协作者的分支往往从较早的点分叉，直接 merge 会回退后续工作。固定做法：

1. 先 `git diff` 审查，**分清「布局意图」与「实现版本」**
2. 逐文件按意图取舍，不用 `--theirs` 整包覆盖
3. 协作者与用户指令冲突时（例如他断言「应显示演示说明」而 U-07 要求删掉）—— **U-xx 优先**，改测试断言
4. 合并后必须重跑全部验证，特别是 e2e（它常内嵌旧版布局的断言）

| 真实 LLM | 赛题演示环境；接口已隔离在 parseIntent 一处，换成 LLM 只改一个函数 |
| 真实 RAG | 未实现，理由同上 |
| 沙箱隔离 | 本项目不生成并执行代码，没有代码执行场景 |
| 真实生物识别 / 加密传输 | 没有硬件与合规资质，做假的比不做更糟 |
| 风控 ML 模型 | 赛题未要求；规则引擎可解释性更强，每条规则都能输出决策链路证据 |
| 引入插画 | 零依赖约束 + 众安自己都只在情绪峰值用（105 条资产里 70+ 给抽奖） |
| 新依赖 | ponytail ultra：白名单之外一律不加 |
