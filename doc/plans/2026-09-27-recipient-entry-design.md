# 完整演示卡号与手动输入

用户要求在同一 mock 中显示完整号码、允许输入卡号，并在数据库增加人物。

- 采用 10 位虚构收款人，每位配一个 16 位数字演示卡号；9900 前缀仅作样例标识，不用于真实银行支付。
- 选择名单 / 手动输入两个模式。输入按字符串处理，允许粘贴带空格的号码，核对卡始终显示服务端匹配的姓名和完整卡号。
- API 只接受 contactId 或 cardNumber 其中一个，未知号码拒绝创建草稿；查询限定当前演示用户，保留幂等和验证绑定。
- PostgreSQL migration 补齐所有现有场景的收款人，不重置余额和交易；已创建的操作快照不篡改。
- 新场景与纯前端模式复用 JSON 种子。数据库新增同用户卡号唯一约束。
- 验证迁移补齐、手动成功转账、未知/非法号码、模式切换、完整卡号、旧幂等请求及手机布局。

## 验证结果

- 迁移已应用到本机 PostgreSQL，alembic check 无差异。
- 29 项后端测试通过，覆盖旧库迁移补齐并保留余额、手动转账、未知/非法卡号、跨场景查询拒绝和旧请求幂等摘要兼容。
- 3 项账本单测、两种模式的浏览器回归及生产构建通过；已检查手机手动输入和完整卡号验证弹窗截图。
- 未提交或推送 GitHub；所有卡号是明确标记的虚构样例。
