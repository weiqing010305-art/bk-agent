# 安全自评报告：权限分级实现说明与已知风险清单

更新时间：2026-10-21。范围：本次对话转账 Agent 及其依赖的本机竞赛后端。本报告描述已实现机制与验证边界，不代表第三方认证或真实银行安全评估。

## 1. 系统与信任边界

前端 React、后端 FastAPI、PostgreSQL；模型为用户指定的 DeepSeek Flash，通过兼容 Chat Completions 的接口提取候选字段。模型没有数据库连接、支付密码、确认工具或执行工具。

用户文本 → 脱敏与提取 → 后端字段校验 → 任务草稿 → 转账核对页 → 用户确认 → 独立密码验证 → 后端原子记账 → 回执。

- 真实模型调用已接入；账户、收款目录和交易均为虚构测试数据。
- 会话是匿名本机演示会话，不是实名认证或银行登录；不得将这个演示服务直接公开部署。
- 卡片冻结、部分订阅/理财/规划功能仍沿用原前端状态，不应宣称已由统一后端权限控制。
- 本次没有修改受保护的产品架构文档，模型只提出候选信息，真实业务数据仍由服务产生。

## 2. 权限分级实现

| 能力 | 权限与控制 | 实现位置 |
| --- | --- | --- |
| 模型提取 | 受限 JSON 结构，只能提出 intent/recipient/amount/note/ambiguous；额外字段拒绝 | backend/agent_model.py |
| 读取任务 | 服务端会话确定用户，按用户、会话和任务 ID 查询 | backend/agent_routes.py |
| 修改草稿 | 校验版本；收款 ID 必须属于当前用户目录；失效旧操作与授权 | backend/agent_routes.py |
| 准备转账 | 后端重新检查必填项、金额、余额、收款匹配；同任务版本生成同一操作 | backend/agent_routes.py |
| 中风险转账 | 当前笔加北京时间当日转出累计不超过 1000 元，需用户确认及支付密码 | backend/transfer_auth.py |
| 高风险转账 | 超过上述金额，额外要求验证码；确认时及执行时均重新计算 | backend/transfer_auth.py |
| 扣款与回执 | 账户锁、事务、唯一操作与幂等约束；结果由账本返回 | backend/transfer_auth.py、backend/models.py |

单笔上限 50,000 元由本次 Agent 金额解析器强制；调用方不能提交风险等级、verified、ownerId 或跳过认证标记。原手动转账仍采用既有的测试验证码路径，不宣称所有业务已切换为新的密码认证。

高风险验证码仍是页面展示的测试码，尚未接短信通道；它只能验证软件分支，不能证明真实多因子认证。原人脸/U盾界面也不是生物识别或硬件认证。

## 3. 数据准确性

手机充值补充：模型只提取当前文本中的候选手机号与金额，11 位手机号发给模型前替换为 PHONE_n。后端校验手机号、金额和余额，缺项不跳转、不默认充值金额；核对页修改会更新版本及支付 ID。实际支付必须匹配所属会话、任务版本、手机号、金额和 ID，重复请求只返回原回执。手机充值沿用原有虚构支付接口和测试密码流程，未复用转账新增的多因子分支及账户级密码失败锁定，不能据转账测试宣称充值已具备这些认证能力。

1. 候选字段必须是当前消息的原文片段；禁止模型补造字段，禁止从“5000”截取“500”。卡号只允许回传服务端建立的 CARD_n 占位符。
2. 金额由确定性解析器转换成整数分，拒绝负值、零、超精度、超限、“一千二”、异常分隔或混合单位；不使用浮点数记账。
3. 收款账户与姓名来自当前用户的虚构银行目录；同名或部分姓名匹配多账户时提供选择，不采用首个模糊结果。
4. 字段齐全不等于有效：余额不足、未知收款人、冲突或歧义都留在收集状态，不能准备执行。
5. 核对页与聊天引用同一服务端任务。关键内容修改后旧交易过期，旧参数摘要与授权不能执行新金额。
6. “再转一笔”新建任务记录，旧任务及回执引用继续保留；历史记录不自动触发转账。
7. 实际转账记账日期使用当前北京时间，不再沿用旧固定日期。其他种子账单仍是固定虚构历史，不冒充实时银行数据。

## 4. 凭据、敏感数据与注入防护

- 模型 API Key 保存在被 Git 忽略的本地 .env/后端环境。用户在设置页输入新密钥时通过独立配置请求交给后端；读取接口不回传密钥，保存后输入清空，关闭时卸载，不写浏览器存储、提示词或日志。
- 完整卡号在发送模型前替换为 CARD_n；聊天文本与持久化草稿进行卡号遮盖。服务端保留业务校验所需字段；普通模型请求不包含完整账本、账户余额或收款目录。
- 正常姓名、金额、备注会发送到用户配置的模型服务商；这并非零数据外发。当前验证仅使用虚构数据。
- 密码在独立 type=password 组件输入，直达认证接口；不进入模型、聊天历史、浏览器持久化或普通审计。请求校验错误不会回显被拒绝的输入值。
- 测试密码默认 123456；首次验证时按账户生成随机盐，用 PBKDF2-HMAC-SHA256（200,000 次）保存摘要。连续三次错误锁定账户验证 15 分钟，跨任务共享计数。
- 授权绑定会话、操作、参数摘要、版本与挑战 ID；交易 5 分钟有效，挑战至多 2 分钟；验证码三次错误终止该操作。
- 备注和模型输出都是数据，不是授权。Schema 拒绝 execute/verified 等字段；密码验证的操作不能绕到旧 OTP 接口执行。
- 模型地址由本机配置入口或部署配置设置，要求 HTTPS（本机服务允许 HTTP），拒绝 URL 内凭据、查询串、片段和自动重定向。更换目的地必须输入新密钥，禁止把原密钥沿用到新地址。
- 设置读写要求有效会话、真实连接地址为 loopback，写入仍受 CSRF/Origin 检查。配置有版本控制，原子替换 .env 并保留其他变量，再同时更新内存；失败不覆盖有效配置。连接测试不写配置，只发送固定测试文本，同一进程只允许一个探测。
- CSRF 头与 Origin 检查、HttpOnly/SameSite cookie、账户归属和数据库约束沿用原后端。

## 5. 重试、异常与审计

- 回合请求 ID 与正文摘要绑定，同请求重试不重复更新草稿；过期版本不能覆盖新草稿。
- 创建/修改任务序列化，准备操作幂等。相同操作重复验证只返回原回执，账本不会第二次扣款。
- 页面中的“确认转账”才可建立认证挑战。模型回复“确认”或“已授权”没有认证效力。
- 网络超时、断开、未知结果只查原操作；不会把未知显示成成功或自动重建第二笔。
- 会话切换后晚到回复只更新原聊天，不抢走当前页面；刷新可重新加载服务端任务。
- 模型缺配置、服务失败或输出不合规均显式失败，不回退到伪装成 AI 的规则回答。
- 审计记录任务更新、草稿准备/失效、用户确认、验证拒绝、扣款结果等事件；不记录模型原始请求、密码或 API Key。当前审计不是独立防篡改日志系统。

## 6. 验证方法与证据

- 本机模型设置：`backend/tests/test_model_settings.py` 共 15 项，涵盖脱敏读取、保留密钥、目的地限制、保存失败、原子持久化、即时生效、版本冲突、清除、远端拒绝、CSRF 和探测并发限制；完整后端现为 88 项通过。
- 设置浏览器专项：`tests/model-settings.mjs` 使用 mock 验证输入、测试/保存分离、失败不保存、密钥不进入浏览器存储、关闭清空、焦点返回、清除和手机布局。另对现有配置执行过固定测试文本的真实连接探测，未保存或修改原密钥。

- 后端：backend/tests/test_agent.py、test_agent_model.py、test_transfer.py 等，在随机隔离 PostgreSQL schema 上检查迁移往返、会话越权、版本、金额、候选选择、密码锁定、风险升级、幂等和事务回滚。
- 模型适配：使用本地 mock HTTP 响应，验证未提供的字段、部分金额、额外权限字段和完整卡号外发被阻止；这不是真实模型大样本准确率评估。
- 真实模型浏览器：tests/agent-flow.mjs，经用户明确授权后使用新建虚构账户；覆盖三轮收集、自动跳转、修改金额、支付密码、回执、确认前无扣款、移动端布局。
- 前端单元：117 项用例。完整验证结果与当前限制记录于 doc/research/2026-10-21-agent-validation.md。
- 安全自评不将“有限用例通过”写成零漏洞、绝对安全或模型正确率 100%。

## 7. 已知风险与后续工作

| 风险/限制 | 当前处理与剩余工作 |
| --- | --- |
| 配置是本机服务全局状态 | 不同演示会话共用配置；未实现管理员身份或每用户配置隔离，禁止通过反向代理将设置入口对外开放 |
| 本机密钥文件为明文 | 依赖运行账户及文件系统访问控制，尚未接入系统凭据库；不宣称已加密保存 |
| 匿名会话、统一测试密码、公开测试验证码 | 仅限本机虚构环境；生产需真实身份认证、独立认证通道、凭据生命周期与部署安全审计 |
| 自然语言误识别和提示注入 | 原文依据、确定性校验和用户核对降低影响，仍需更大规模带标注评测与对抗测试 |
| 自由文本中的秘密无法完全识别 | 已拦截明显密码/验证码表达并脱敏常见卡号；不能保证识别没有标签的所有秘密 |
| 一次消息多个目标、复杂预约/跨币种 | 当前只支持单笔人民币即时转账，不保证所有语言表达均能正确分类；由用户最终核对 |
| 模型可用性、耗时和费用 | 当前调用有超时和输出长度限制；尚未实现生产级用户配额、全局限流及成本监控 |
| 持久化数据与日志 | 本机 PostgreSQL 与浏览器历史尚无应用层加密、自动保留期清理或独立防篡改审计 |
| 非 Agent 的旧业务 | 一些能力仍是前端演示或使用旧测试认证，不能据本次 Agent 测试宣称全站安全达标 |
| 真实收款身份与账户约束 | 当前只查询虚构目录和单一人民币资金账户；未接真实银行身份核验或多卡独立余额 |
