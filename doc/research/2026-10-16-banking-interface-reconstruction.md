## 观察、推断与落点

| 官方来源中的观察 | 对青禾的设计推断 | 本轮实现 |
| --- | --- | --- |
| [汇丰新版 App 功能指南](https://www.hsbc.com.hk/zh-hk/ways-to-bank/mobile-apps/banking/features/)将首页、转账、银行卡、财富等作为清楚的主要分区，并展示常用户口与快速链接 | 账户信息旁应有直接操作；高频服务应容易寻找 | 余额区增加转账、银行卡直达；全部 13 个入口保留，支持服务名称及水费、挂失等别名搜索 |
| 同一指南将银行卡功能集中到卡片分区，并展示账户总览及多种服务入口 | 选中对象与可用操作应靠近，减少上下寻找 | 卡片页原冻结、限额、挂失等动作提前到详情开头；桌面四列、手机两列；原切卡、键盘及确认逻辑保留 |
| [汇丰 App 介绍](https://www.hsbc.com.hk/ways-to-bank/mobile-apps/banking/)介绍账户偏好、快捷操作与隐藏余额 | 青禾首页金额隐私应覆盖关联汇总，而非只遮住一个大数字 | 可用余额、资金安排、账本摘要、动态金额同步隐藏；占比图同时收起 |
| [ZA Bank](https://bank.za.group/en/)和 [ZA Card](https://bank.za.group/en/za-card)公开页面采用清楚的业务入口和独立产品对象呈现 | 借鉴信息分组与对象识别，使用已确认品牌；营销页面不直接搬入办理界面 | 首页账户、服务、账本与动态分层；支付银行卡用卡名和尾号呈现，仍由原生下拉控件选择 |
| [Zarm 官方仓库](https://github.com/ZhongAnTech/zarm)提供基于 React 的移动端组件体系 | 采用一致的控制尺寸、选中状态和移动端反馈，而非引入第二套 UI 系统 | 共用表单、金额输入、主按钮、核对和回执样式；不安装 Zarm，不复制其代码或营销素材 |

搜索别名、三色收支摘要、付款卡呈现等是青禾的设计适配，不宣称这些银行存在完全相同的组件。没有从公开介绍中推导新的风控规则；支付密码、重复提交保护、失败查询仍由原项目承担。

## 设计约束与具体交互

- 沿用薄荷绿、浅蓝、暖杏：操作用薄荷，账本信息用浅蓝，计划及动态提示用暖杏。业务图标仍统一薄荷方底绿线；服务区域不铺独立的大色块。
- 概览按整个视口居中。1440px 检查时账户区宽 1140px、中心点 720px；内容滚动区起点 128px，位于助手问候底部约 121px 之后。大屏及手机分别适配，手机预留助手操作区。
- 搜索即时筛选但不自动跳转；无结果有明确反馈，Escape 清空并保留焦点。实际点击才进入原业务路由。
- 最近账期摘要来自同一本账的交易，明确显示年份和月份；显示账本收入、支出与支出分类。它不是资产总额，也不推测预算。空账本显示空态。
- 六类生活服务沿用填写、核对、回执。银行卡选择保留原生键盘行为；错误、返回修改、再次缴费与未知结果查询保留。没有缴费记录时说明图表何时产生，不生成虚构趋势。
- 没有新增 Agent、自动代办或新的模型调用。聊天及会话历史沿用已有实现。

## 实现与验证

`HomeServices` 管入口与搜索，`HomeInsights` 和 `overviewInsights` 管账本派生汇总，`PaymentAccount` 管已有付款卡选择的展示。`bankingExperience.css` 统一业务页交互外观；`qinghe-ui-preview.css` 管概览布局。受保护产品架构未修改。

已完成 116 项单元测试、全 13 项业务入口与手机溢出检查、搜索和金额隐私检查；生活缴费核对/付款/再次缴费/分类/月份、卡片键盘及状态、储蓄编辑等由产品 UI 测试覆盖。后端集成检查覆盖数据库读取、两种转账入口、刷新及丢失响应恢复、充值、储蓄存取和会话隔离。

最终构建通过，102 张文档 Mermaid 通过解析。旧 e2e/text/copy/smoke/flow/motion 六个脚本仍假定有侧栏或默认聊天首屏，运行在入口处超时，未完成对应断言；原始结果见 `artifacts/bank-research/required-checks.json`，不记为通过。新版产品检查不替代旧套件全部聊天、字数、禁用词和动效断言。

原有持久化边界继续保留：银行卡配置和部分业务元数据仍使用原本的本地状态。此改版不代表所有业务都新增了后端持久化能力，也不代表银行原生 App 的真实流程已经完整复现。
