# Agent 输入实测 · 2026-10-22

使用本机配置的真实模型、8080 合并应用和新浏览器创建的独立虚构账户；不连接真实银行或运营商。测试手机号在模型调用前替换为 PHONE_n 占位符。以下为实际执行结果，有限样本不代表通用识别准确率。

## 转账闭环

输入“我要转账”→追问收款人；“王佩兰”→追问金额；“500元，备注房租”→自动核对。页面修改为 123.45 元，用户确认并在验证窗口输入测试密码后完成。核对前余额不变，最终扣款 12,345 分、流水新增一笔。另测手机宽度、一次说齐收款人/金额、新聊天与延迟回复隔离均通过。末项延迟回复隔离使用本地拦截，其余转账业务使用真实模型和后端。

## 手机充值闭环

| 操作 | 实际结果 |
| --- | --- |
| “我想手机充值” | 识别 phone，缺手机号和金额，先问手机号 |
| 虚构号码 13800000000 | 仅缺金额，追问“充值多少钱？” |
| “五十元” | 提取 5,000 分，自动进入充值核对页，未扣款 |
| 页面改为虚构号码 13900000000、30 元 | 任务版本和支付 ID 更新，核对金额为 3,000 分 |
| 使用旧草稿提交 | 后端返回 409，无扣款 |
| 输入错误测试密码 | UI 提示错误；直接调用后端也返回 422，无扣款 |
| 正确测试密码确认 | 后端成功回执，余额减 3,000 分，流水新增一笔 |
| 重复提交同一支付 | 返回原回执，余额不再变化 |
| 返回聊天并重新打开充值 | 可查看原成功回执；新聊天保持空白 |

上述手机链路没有 mock Agent、支付或账户接口。回执截图：`.local/agent-phone-live-complete.png`；逐轮结果：`.local/agent-inputs-live-results.json`，均位于 Git 忽略目录，不包含密钥或密码。

## 另外九组真实模型输入

| 输入 | 实际结果 |
| --- | --- |
| 给王佩兰转100元 | 准确生成 100 元转账核对草稿 |
| 给13800000000充50元话费 | 准确生成 50 元充值核对草稿 |
| 给王佩兰转一千二 | 不猜金额，要求明确金额 |
| 给王佩兰转0元 | 拒绝无效金额，继续追问 |
| 给王佩兰转50000元 | 提示余额不足，不开放确认 |
| 给不存在的收款人测试甲转10元 | 提示找不到匹配账户 |
| 我想手机充值，手机号12345，金额50元 | 保留金额，要求有效 11 位手机号 |
| 我想交水费 | 提示使用首页其他业务入口，不生成转账确认动作 |
| 明天给王佩兰转100元 | 不擅自降级为即时转账，提示使用其他入口 |

两组合法草稿均验证“取消”后不可办理；九组输入均未记账。脚本中的每组输入独立创建聊天，不混用历史字段。
