## 追加：手机充值截图问题修复

- 根因：后端只登记转账，前端又对所有任务显示转账链接；现新增 phone 业务类型及 can_open 动作条件。
- 94 项后端、117 项前端单元、手机充值浏览器专项、十三业务 UI、111 张 Mermaid 与构建通过。
- 手机充值专项用 mock API 验证手机号/金额追问、无默认充值金额、自动进入核对页、页面修改、错密码不提交、带任务版本的确认请求及正确业务链接。
- 后端隔离数据库验证实际支付、回执、余额变化、重复提交、旧版本和跨用户请求拒绝。手机号脱敏适配用本地 mock 响应验证，未向模型发送号码。
- 真实模型验证“我想手机充值”识别为 phone、“五十元”在充值上下文识别为金额续答；原转账实时模型浏览器闭环也通过。没有连接真实运营商。

## 实施边界

- Agent 首版支持单笔人民币即时转账；其余业务保留原页面/交互，未都接入模型。
- 密码验证是真实后端校验，但认证对象是虚构账户，默认测试密码 123456；高风险验证码为页面展示测试码，并非真实短信多因子。
- 真实模型联调是有限成功路径验证，不是大样本实体识别准确率报告。模型输出对抗检查由 mock 响应覆盖，不能据此宣称所有提示注入均被阻断。
- 第一次联调曾被自动审批拒绝；用户明确允许虚构数据外发和测试账本变更后完成。没有通过替换工具或隐蔽执行绕过审批。
