## 2026-09-28 · 卡片页重构：用图形代替文字（613 字 → 133 字）

**问题**：卡片页是全站界面文案最多的一页（613 字，比第二名高出一倍）。
逐条数下来，绝大多数不是用户要读的信息，而是**设计没做到位、用文字补的说明**：
「选中的卡会浮起……」（32 字）、「冻结与解冻都会留痕……」（24 字）、
时间线每个节点的说明句（49 字）、四个渠道各一行「今日可用 ¥X / ¥Y」（40 字）、
三行限额各一句解释（22 字）、「以上为本卡近 10 笔中的前 6 笔」（17 字）。

**改法**——额度尺是这一页唯一做到「用设计代替文字」的组件（针 / 块 / 尺度），
其余部分照它的思路重做：

| 原来写的 | 现在画的 |
|---|---|
| 「本账期还有 29 天，11 月 4 日还款」+「距账单日还有 29 天」 | `CardCycle` 账期条：账单日 → 还款日的进度 + 终点日期 |
| 档案面板「标签：值」六行 | `CardFacts`：图标即标签（账户 / 账单日 / 有效期 / 上期账单） |
| 每渠道一行「今日可用 ¥31,540 / ¥50,000」 | 使用条 + 剩余额 + 开关状态（图标即渠道名） |
| 时间线节点说明句 | 节点图标（冻结 / 解冻 / 激活 / 提额 / 换卡 / 验密 / 境外）+ 两个字的动作；细节走 `title` 与 `aria-label` |
| 「隐藏卡号与金额」按钮文字 | 眼睛图标本身 |
| 「演示数据」「演示日期 9 月 26 日」 | 删除 |

**同时删掉的**：挂失补卡（点下去只有一个 toast 的死按钮）、
「剔除本期后的可用」（额度尺已经答过）、三个动作格的小字副标题、
三个限额行的小字解释、卡面上「持卡人 / 有效期 / 卡组织」三个字段名（三张卡各写一遍，零信息）。

**顺手修掉一个真 bug**：结果态的「撤销冻结」原来调的是同一个动作，
点下去是把卡**再冻结一次**而不是解冻。现在撤销走反动作（`onConfirm('unfreeze')`），
e2e 之外补了一次真实浏览器验证：冻结 → 即时反馈 → 撤销，历史时间线正确留下两条。

## 2026-09-28 · 交易头像体系（情绪价值）

**这一轮的判断：流水里「每一笔都有形象」不是装饰，是分类的可读性。**
依据是 doc/research/revolut-ai-and-za-deep-dive.md §D —— 产业界真实在跑的四个实现。

### 双轨制：商户形象 + 类别兜底（Plaid Enrich 的官方结构）

Plaid 的 `logo_url` 与 `personal_finance_category_icon_url` 是两个字段同时给出，不是二选一。
新增 `views/avatars.jsx`：有商户就上商户形象（品牌色 + 字标），识别不出才退到类别图标。
**数据缺失三级降级**按 Monzo 的原话实现：品牌名+品牌色 → 商户名+类别色 → 类别名+类别图标，
`cleanName()` 会把 "WM SUPERCENTER #1700 POWAY CAUS" 这类串码判成不可显示 —— 原始串码一次都不露面。

### 分类对齐 Plaid PFC，从 6 类扩到 16 类

`category` 直接用 PFC 的 16 个 primary 英文常量（`RENT_AND_UTILITIES` / `TRANSPORTATION` /
`INCOME` …），中文名只做显示，账本里现有的中文旧分类由 `LEGACY` 兜住 —— **旧数据一个字段都没改**，
将来接 Plaid 或银行开放 API 零转换成本。同时把「**周期/订阅**」显式做成标签（`recurring`）而不是类别：
它跨越房租、云空间、光影视频。

### 形状系统（§D-54）：圆角方形是零文字的分类手法

圆 = 商户消费 / 类别兜底 / 收入；**圆角方形 = 周期性**；人物位 = 转账给人。
所以云空间、光影视频、随听音乐一眼就能从一堆一次性消费里分出来，不需要任何文字。
「地铁与打车」用地铁的头像 + 一枚打车小标，一行说清两种交通方式；地铁这类高频小额**连小标都不加**。

## 2026-09-28 · Agent 统合视图 + 图表化账单 + 多 Agent 分工

**这一轮的核心判断：之前做的是「把聊天当输出通道」，不是 AI Native。**
每办一件事就往对话里贴一张卡，看到第三张就得往上滑 —— 那违背最小操作原则。

### Agent 统合视图（agent/brief.js）

软件时代的银行按「产品」切信息：余额在账户页、账单在账单页、订阅在订阅页，用户自己拼。
Agent 时代按「用户此刻要办的事」把跨产品的信息合起来。所以每个 compose* 都刻意跨域取数：

- **首页** = 一张状态板：余额 / 本月支出 / 待扣订阅 + 需要留意的 + 最近三笔
- **账单** = 结论在前、分析居中、明细在后；结论句会把订阅这个「另一个产品页的事」拉进来
- **转账核对** = 不只收款人和金额，还给「转后余额」「本月支出会变成多少」「扣完订阅还剩多少安全垫」
- **转账回执** = 钱去哪了 + 账户现在什么样 + 接下来你可能想做什么

### 工作区模型（取代无限增长的聊天流）

助手页从「一条会滚走的聊天流」改成 **工作区 + 一行可切换的历史**：
工作区放当前这件事的统合视图（一屏看全），历史折成一行 chips，点一下换回当时那张视图，
并给一个「回到最新」。**不滚动的历史，可切换的现在。**

### 图表化

新增 `views/charts.jsx`：手绘 SVG，零依赖。圆环 / 条形 / 累计折线三种形态，
**共享同一个「当前分类」状态** —— 鼠标滑过任一形态的任一段，图例、中心数字、扇形一起响应。
账单页顶部有形态切换 tab。

### 卡片与卡包

卡片补上了真实银行会有的字段：额度、本月已用、可用渠道、发卡日。
卡包可切换，选中的卡浮起；卡片页有额度统计条、卡片事实、操作宫格、这张卡的流水。

### 动线必须是无感的

删掉了右侧的「动线面板」和侧边栏的「隐藏动线面板」按钮 —— 那是我把「动线」理解错了。
动线是用户体验的顺滑度，不是给用户看的流程图。

### 修的真 bug
