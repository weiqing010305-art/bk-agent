# 青禾视觉规范

## 2026-10-16 账户首页与办理界面

模式为 Operate：用户先看清账户和操作对象，再直接办理。沿用已确认的三色体系及助手形态，不新增品牌色、字体、组件库或独立大色块入口。以下是本轮实际组件和样式的布局补充，覆盖历史同名布局描述；色值以 `tokens.css` 和下节三色表为准。

| 区域 | 当前实现 |
| --- | --- |
| 概览 | 整个视口居中，内容容器最大 1184px；标题独立于滚动内容。桌面所有宽度均为助手问候预留 128px 顶部区域，避免大屏断点取消避让；标题保持顶部居中 |
| 账户区 | 桌面余额与资金安排两列，46px 余额、20px 圆角；手机单列、38px 余额、16px 圆角，三项安排横向并列 |
| 全部服务 | 白底、统一 44px 薄荷图标；桌面日常七列/资产六列，手机四列/三列；搜索位于标题旁，手机独占一行 |
| 收支一览 | 连续浅蓝信息区；标明账期，收入与支出用等宽数字；分类条同时有文字及金额，隐藏金额时不显示占比 |
| 业务页面 | 容器最大 1240px；标题 28px（手机 26px），面板 16px 圆角、单层边界；分区由留白和轻色标题带组织 |
| 办理控件 | 字段 14px，普通输入至少 48px，金额输入 32px；按钮至少 44px、10px 圆角；表单底部主操作手机铺满可用宽度 |
| 付款卡 | 浅蓝信息面、卡名及尾号；原生 select 覆盖整个选择区，键盘焦点在外层可见，保留冻结卡不可选 |
| 卡片动作 | 紧邻当前卡片详情，桌面四列、手机两列；冻结和原管理功能均保留 |
| 手机安全区 | 概览及业务滚动内容为底部助手保留 96px，避免固定控件覆盖字段或主按钮 |

颜色职责保持薄荷操作、浅蓝信息、暖杏计划。新的余额区取消阴影，服务和业务面板使用细边界；业务图标仍为 `--icon-bg: #E1F7EE` / `--icon-ink: #087F67`。焦点、文字选择和输入光标使用已有绿色 tokens，错误保留语义错误色。遵循减弱动态设置，不加入无业务意义的连续动画。

实现对应 `HomeServices`、`HomeInsights`、`PaymentAccount`、`bankingExperience.css` 与 `qinghe-ui-preview.css`。业务统计来自原账本，空态不编造记录；原助手、会话历史、授权和后端边界不变。[研究与设计依据](research/2026-10-16-banking-interface-reconstruction.md)。

## 2026-10-14 三色存在感强化

用户要求概览和功能页不再过于朴素，同时保留薄荷绿、浅蓝、暖杏。提高三种色系的明度内色彩辨识度：余额卡的薄荷至蓝渐变更鲜明，业务页用标题带、信息读数、选中态和计划提示体现色彩。全部首页入口仍是白底及原统一薄荷图标，避免恢复此前被否定的整排彩色入口卡。

| 色彩角色 | 当前值 |
| --- | --- |
| 薄荷操作区 | `--surface-mint: #CFF2E5` |
| 浅蓝信息区 | `--surface-info: #DFEEFC`，图表 `--palette-blue: #82B7E6` |

生活缴费的汇总是连续薄荷/蓝信息区，表单标题为薄荷、历史标题为暖杏；充值/转账突出操作绿，账单/卡片/信用卡/兑换突出信息蓝，储蓄/订阅/预约/出行/理财突出计划杏。白底依然承载表单和明细，重点金额、筛选与按钮加强对应色系。组件不写色值，`colorHierarchy.css` 统一管理展示规则，不改布局、内容、金额或请求。

本节覆盖下文历史表格中的旧色值。图标 `#E1F7EE/#087F67`、助手品牌入口及十三业务入口继续沿用已确认值。

## 2026-10-14 业务可视化与手动交互

依据产品讨论完善独立业务页，以生活缴费作为本轮重点。首页白底服务入口与悬浮助手保持既有形态；业务图标继续统一薄荷底和绿线，水电燃气的图表以薄荷、浅蓝、暖杏区分，并同时显示文字和金额。

- 生活缴费：上方按月支出构成与连续六个月趋势，下方填写/核对/回执与可展开记录。桌面双列、手机单列；缺记录显示空态，不假设欠费；再次缴费仅预填户号和类型。
- 六类生活服务：共享三步进度与完成回执，保留返回修改、密码错误和未知结果查询，进度改变后聚焦办理区域。
- 银行卡：卡名、当前选择、使用状态和字段名称可见；支持方向键、Home/End 切卡，焦点与详情同步；显隐覆盖卡面、档案、额度和流水。近期交易读取同一账本，不再使用独立固定流水。
- 储蓄：目标日期、已存/目标、进度、剩余金额和每月参考额分层呈现。到期不再给出未来月计划；修改定位表单，创建、存取、删除功能保留。
- 账单：分类筛选覆盖实际交易类别，日净支出显式保留负号。
- 手机业务页为悬浮助手和返回概览留出 96px 底部操作区，返回按钮并列于圆形助手左侧；滚动内容止于操作区上方，避免覆盖表单和开关。首页及助手对话布局不变。

本轮只实现业务 UI 与手动路径；未增加 Agent、模型调用或新的对话衔接。银行卡配置额度、渠道和档案元数据仍沿用原本的本地数据范围。

用户提供 ZA Group 参考，要求颜色明亮清晰、不要太深；随后要求改善整体单调感，采用三种颜色增加层次。当前采用薄荷绿、浅蓝、暖杏与白底，账户、服务宫格、动态及聊天交互沿用现有结构。

## 三色的用途与覆盖范围

薄荷绿承载操作和统一业务图标；浅蓝承载信息、表单核对及助手欢迎区；暖杏用于计划留存、动态提示、订阅扣费日期和储蓄计划。白底与中性浅背景保留阅读留白，辅助文字改用可读的中性色，避免整页泛绿。

用户随后指出资产管理整排蓝色块过于花哨：六个入口恢复白底上的图标与文字，不铺独立的大色块。保留原布局、统一薄荷图标，以及轻量的悬停和键盘焦点反馈。

余额卡保持浅底深字，用薄荷至浅蓝渐变体现两种主色；计划留存使用暖杏小标签。业务图标仍统一为 `#E1F7EE` 方底与 `#087F67` 线条。卡面沿用原有薄荷、浅蓝和暖杏分工，移除旅行卡的深色底；图表分类继续有标签，采用三个色系的深浅变化。成功、警告和信息文字使用相应色系的可读深色，失败仍保留红色语义。

本轮改变配色及静态呈现，不改变业务入口、表单步骤、金额、后台请求或 Agent。三色表示主题色系，不要求将白底、文字和错误状态也压成三个色值。

2026-10-13：根据用户的新草图，移除导航列表和历史对话区域，全局入口改为悬浮圆形青禾标记。桌面左上方显示圆形入口及问候气泡，首页内容下移为气泡留出空间；窄屏入口固定在右下方，首页问候显示在上方。业务功能从首页宫格进入，非概览页提供小型返回概览按钮。对话仍是连续消息流，共用同一账本。

用户最新截图覆盖此前图标规则：全部服务入口、交易/订阅/卡片列表、助手业务卡片图标统一为浅薄荷绿实色圆角方底和绿色线条（桌面服务 44px，列表 40px，圆角 12px）。移除动作圆形底、商户彩色渐变、工资金币装饰；类别图形、商户/人物名称、功能路由及金额语义继续保留。助手品牌入口沿用悬浮圆圈位置，配色同步为浅薄荷绿。图标令牌为 `--icon-bg`、`--icon-ink`、`--icon-radius`。

用户最新要求：圆形入口与问候气泡保持固定，样式、文案不变。桌面为它们保留独立左侧空间，业务滚动容器从视口顶部开始，避免气泡覆盖内容。窄屏问候使用独立顶部区域，业务从其下方滚动；圆形入口仍在右下方。

桌面概览初始位置在主内容区最顶部，只保留常规页面内边距，不添加问候占位或额外顶部留白。

用户进一步明确：整个概览内容列（标题、余额卡、服务宫格、动态）在整页水平居中，而非只居中标题。取消左侧占位，左右滚动条空间保持对称；桌面按助手所占空间限制内容宽度，较窄窗口将业务区放到助手下方，避免遮挡。

主题取值集中在 `src/styles/tokens.css`，组件只引用令牌。Figma 使用可用的 Noto Sans SC；本机应用沿用系统中文字体，因字体环境不同，云端设计稿的字宽可能略有差异。

## 2026-10-13 主界面精修样稿

用户要求先完善美术与交互，全部业务功能保留，暂不开发 Agent。用户随后确认将这版作为前端并接后端：`src/main.jsx` 统一载入精修样式，默认首页为概览；`qinghe-ui-preview.html` 保留为同一 App 的别名，不再通过观察器自动跳回首页。两种入口共用薄荷绿主题、布局和原有业务。

宽屏将 13 个原入口按现有 action/product 属性分为日常服务 7 个、资产管理 6 个。手机改为每行 4 / 3 项。业务路由、表单、确认、风险门禁、数据模型与现有动效均复用；优化卡片间距、文字层级、悬停和键盘焦点。金额显隐、动态就地展开及全部明细保持原事件处理。

Figma 插件在写入新稿时返回 Starter MCP 调用额度耗尽，精修稿未完成云端写入。工作区 `design-samples/qinghe-refined-figma.svg` 是从预览页面几何信息导出的可导入矢量稿，并非已同步的 Figma 原生组件；`refine-home-figma.js` 是待执行的原生设计构建脚本。旧 Figma 文件继续作为上一版本。
